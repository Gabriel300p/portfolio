Technical questions to rehearse

The following are reasoning exercises inferred from the role, not Brex’s confirmed interview questions or claims that these mechanisms are implemented in Pandora.

1. A tool call succeeds, but the worker crashes before recording success. What happens next?

Separate an execution attempt from the business operation. Discuss a durable operation identity and provider-supported idempotency where available. If the outcome is ambiguous, query or reconcile the external state before retrying. A local lock alone cannot provide exactly-once behavior across an external service.

2. Which failures should be retried?

Classify transient failures separately from invalid configuration, invalid input and authorization failures. Discuss bounded exponential backoff with jitter, deadlines and attempt budgets, plus reconciliation or a dead-letter path. Retrying a missing executable indefinitely is not recovery.

3. What makes the discovery fix safe?

Explain the gap between “connection started” and “registered.” Then discuss atomic ownership acquisition, cleanup on failure, and behavior across processes. The operational diary establishes an in-progress ownership filter; it does not document a distributed lock or lease. Be explicit about that boundary.

4. How would you evaluate an agent?

Start with representative tasks, versioned inputs and expected constraints. Separate deterministic checks—schema validity, forbidden actions, correct identifiers—from outcome quality. Track tool traces, latency and cost; compare model/prompt versions, review ambiguous labels, and hold out cases. A model grading itself is not sufficient ground truth.

5. How would you authorize tools?

Enforce permissions server-side using the caller’s identity, scoped capabilities and resource boundaries. Model text must not grant authority. Discuss credential lifetime, audit records and additional controls for high-impact actions. Do not claim deployed RBAC without an implementation you can demonstrate.

6. What would you monitor?

Distinguish process health, queue progress, completion rate and business outcome. Include age of oldest work, retry volume, timeouts and cost per execution. The Tempo example illustrates why ingestion health does not prove that trace search works.

7. How does frontend experience help a platform team?

Use Acesso’s shared components and design system as an example of consistent interfaces and reuse. Connect that experience to understandable SDK/API contracts, error messages and documentation. Do not equate interface reuse with proof of operating distributed backend infrastructure.
